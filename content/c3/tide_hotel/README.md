# 潮汐旅馆：第九声钟响

1～4人悬疑调查故事，建议完整阅读与查证预计 30～60 分钟。建议2～4人合作，保留单人调查路径。每个角色只供一人扮演，可选择声音记者徐闻、地方档案研究员沈砚、救援志愿者许澄或纪实摄影师陆遥，暴雨封岛之夜赴作家江临的约，却在第九声钟响后听说对方失踪。画面采用海岛旧旅馆、冷色海雨与暖色室内灯的统一方向。

- 8 个场景：接待厅、海景餐厅、二楼走廊、209客房、护理室、地下机房、阁楼资料室、旧船屋。
- 4 位在场人物：旅馆经营者林素、护士陈雾、电工赵朔、退休船长何泊。人物采用预设条件对话，掌握新证据后可以回访，不依赖运行时大模型。此本的人物留在各自场景，不作随机移动。
- 36 项有独立叙事反馈的预设互动（含4项角色专属说明）、22 条主线线索、209实体钥匙、4份私人角色本与8份分幕回忆、密码互动与一次可选概率判定。
- 26 张采用的 AI 生成图片覆盖所有场景、人物、预设互动、关键证物与结局。每次互动都有配图绑定；相关交互共用同一证物/人物图，三个关键段落使用专门剧情图。
- 3 个最终抉择结局、提前离岛、调查未完成，共 5 种结局。

时长是阅读与探索估计，不是经真人计时确认的结论。本次文字修订后，公共开场与行动叙事约6100字，新增四份完整角色本、两轮私人回忆和角色尾声，另有线索回看、结局和场景描述。30～60分钟为包含探索、比对与回访的原定体验估计，角色版的实际时长尚待真人试玩确认。快速跳过全文或提前离岛会明显短于30分钟，不强迫玩家等倒计时。

## 图片与复现

图片通过内置 `image_gen` 服务生成，最终素材存于 `apps/mobile/assets/stories/tide_hotel/`。完整提示词见 `art-prompts.json`，修订提示见 `art-revisions.json`。文字证据由游戏文本准确提供，纸面图不承担可读文字或密码校验，图片不包含服务端密码。

`story.json` 是可直接导入工作台的完整 C3 内容。`roles.json` 保存四人的公开简介、私人经历、分幕回忆、说明选择和各结局尾声。`python3 scripts/build_tide_hotel.py` 根据主线作者文本、角色文本和已经落盘的图片生成 JSON 与图片哈希清单；该命令不重新调用生成服务。更换素材需新建版本文件，避免改变已经冻结的故事画面。

`node scripts/publish_tide_hotel.mjs` 在本地已有 Core 和忽略目录的管理员凭据下发布，并通过真实 HTTP 验证五个结局和2/3/4人完整路线。素材发布只允许与服务端内置清单匹配的图片；任意远程 URL、未登记图片与不匹配的哈希不会通过。

## 作者说明：以下包含剧情答案

故事时间为2023年，旧案发生在2008年9月21日。丁远于2016年病逝。年龄与十五年前的经历依此编排。

今夜的失踪与旧案的责任是两条时间线。江临安排预录钟声，后经后山避险；林素人为断电并掩盖旧案，但不能因此推断她在今夜杀害江临。赵世衡曾在22:10活着上岸，22:35被带离，23:05救援被暂停，名单随后改写。现有证据支持重新调查扣留、延误与改写，不能代替具体死因和责任的正式查明。

### 主线依赖与反卡关

1. 林素首访取得209钥匙，才能进入客房。停钟调查与机房日志分别建立时间锚点。
2. 客房稿纸允许核对旧护理页；原始录音允许向何泊核对离开。药物与绳索调查用于排除误导。
3. 客簿给出铁柜密码的月日线索。输入0921可开；六次失败仍可按维护页拆锁。拆锁不需要随机成功。
4. 柜内原始救援页、名单、护理页与录音齐备后保存副本；旧护理页、名单、未寄信与剪线证据齐备后回访林素。
5. 何泊的离开证词加上后山通路证物，允许应急电话确认江临安全。双方时间线、副本与林素回访完成后才能重建并作最终抉择。
6. 修电为可选判定，70%成功。失败仍可手动读取计时卡，两条路线相同地获得关键信息。

阅读弹窗和打开线索/物品/历史不扣余力。图文叙事在团队公共阅读屏障内暂停行动倒计时，回合是离散调查预算，不是现实分钟。正常完整路线约9～10回合，预算为24回合；耗尽预算进入“调查暂时中止”，不假称查明真相。

“提交核实材料”“七日封存交接”“误指今夜谋杀”为三个最终选择；结束操作的风险文字明确说明会结束本次故事。提前离岛也有单独确认。结局后仍可回看自己的手记。

## 1～4人协作规则

- 最少1人、最多4人；当前加入者选角并准备即可开场。单人可选任意角色，全部角色均有完整通关路径。开场冻结实际角色名单，未选角色不会占行动步或等待阅读确认。
- 四名玩家角色与四位NPC是不同实体；NPC仍在各自场景提供预设对话。玩家先阅读各自的私人角色本，再阅读公共开场。每人有两轮私人回忆、独立目标和餐厅的专属说明选择。角色本与回忆可主动分享，没有互相依赖的必选角色。
- 可分头移动、询问在场人物；调查反馈和新证据只向当时同场的玩家展示，不自动发送给远处同伴。通过线索册主动分享后，接收者才能使用对应证据推进自己的调查；分享不要求同场，也不消耗行动点。私人角色本与回忆只在拥有者和主动分享的接收者中展示。物品实体由执行者保管，不影响已分享证据文字的使用。
- 同一步同时调查同一内容合并为一次事件与一段反馈；已经完成的调查从全员可选行动中移除。每人保留独立行动点，未决定者需要提交行动或结束本回合。
- 结局抉择与提前离场要求全员在相应地点一致提交同一方案。意见分歧取消本次终局执行、保留继续调查的机会。单人时所需参与人数为1。
- 已经创建的房间继续使用绑定的发布版本。体验本次角色版需先发布新版本，再新建房间；网页支持分别新建标签页，以不同游客身份加入同一邀请码。

## 阅读与地图界面

- 主画面以当前位置入口取代缩小的路线图。点击展开地图，手机默认聚焦当前位置、以可读比例显示节点；可拖动、缩放或一键适配全图。地点标签提供固定大小的触控入口，选中后显示详情、通路限制及移动费用，确认移动只提交一次。
- 地图只使用服务端允许展示的地点和道路。双向通路合并为一条连接，分支按实际连接关系排列，不推测未发现的地点。
- 人物对话的桌面布局为完整竖幅肖像与文字并排，手机采用上下排列；人物图使用contain展示，不裁掉头部或身体。
- 叙述、地点说明和线索详情使用富文本。`**重点**`显示暖金色加粗，`==证据==`显示浅青色加粗，24小时制时间自动突出。逐字阅读按可见文字计算，不展示格式标记；未标记文字原样保留，不执行HTML。

## 角色版内容组织

- 选角页只展示公开身份与赴约缘由，已占用角色展示扮演者并禁用；服务端以房间事务锁拒绝重复选角。开场后不能重新选角。
- 第一幕“第九声钟响”：各自阅读完整角色本，随后进入共同的23:40失踪现场。公共文本不预设所有人都有录音笔或同一封邀请信。
- 第二幕“岸上的名字”：首次核对旧护理页后，公布阶段转折，分别发放角色回忆。
- 第三幕“留下什么”：证据副本保存后，分别发放第二轮私人回忆。每人可回餐厅说明自己过去隐去的事情，也可保留；个人说明不是完成主线的条件。
- 每个公共结局附一段本人可见的角色尾声，并依据是否作过个人说明切换文本。其他角色的尾声不进入当前玩家快照。
- 单人时只发所选角色本，不冒用缺席人物经历；所有关键证据仍可在现场取得。缺席角色不参与阅读等待、行动或终局表决。单人、双人、三人和四人均有路线测试，但真实阅读时长仍待试玩。

### NPC 即时互动与可见性

NPC 的单人提问立即扣除余力并反馈，不占用全员行动队列；多人协作行动仍按原规则结算。公开交谈只向执行时位于同一场景的其他玩家发送简短通知，回答弹窗仅展示给发起人。角色限定行动默认隐秘。其他隐秘互动可通过 `c3_settings.npc_interactions.<action_id>.visibility = "private"` 配置；需要协同结算的 NPC 行动可设置 `execution = "round"`。隐秘互动的回答和新线索只发给执行者。

209 钥匙属于物品，首次交谈后由执行者持有，可按物品规则转交；林素授予的查看房间许可对调查队伍生效。同一钥匙不会因重复操作产生多份。已开始的房间保持原发布版本的剧本数据，体验物品归类调整请使用新版本创建房间。

线索与实物复核：磁带、209 钥匙、证据副本与林素交出的文件袋均有独立物品及发放效果；照片、稿纸、护理页、收据等只查看或拍照的材料仍以线索记录。目击或同伴分享的线索只更新线索册角标，不自动打开阅读弹窗；场景行动回响仅发送给执行者。
