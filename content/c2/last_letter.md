# 雨夜最后一封信

短篇单人三幕故事：雨夜来信 → 雨水中的选择 → 迟到的告别。只需一名“值夜人”，不依赖模型服务或其他玩家。

你一直以为母亲二十年前抛下了你。旧邮局停用前的最后一夜，门缝下出现一封写给你的旧信，外面的邮戳却是新的。调查要回答两个问题：母亲为什么没有回来，谁把这封信送到了门前？

## 操作与节奏

选择值夜人，点击“走进故事”。调查推进时间；剧情阶段自动切换，单人页面不显示“结束回合”按钮。地图在获得钥匙后出现档案室，移动会自动使用已持有的钥匙。余力不足以抢救物品时，可用场景行动“停下来等一阵雨”推进时间。

线索册、随身背包、行动记录各有独立入口和内容。格子先显示名称，选中后阅读详情；行动记录来自服务器个人结算，刷新后仍可回看最近 80 个结算中的个人行动。

## 剧情规则

- 新邮戳与所救下的证据需要联系起来才能作出完整判断。
- 抢救投递簿与抢救录音带互斥，会保存不同证据和实际物品；选择前明确确认代价。
- 判断“她离开了我”会留下未解释的矛盾，允许重新思考。
- 是否看过合照，会改变告别时是否直接认出送信人。
- 雨水与停电随时间发展；场景亮度、章节、描述随进度变化。
- 投递或珍藏是最后的选择，前面的抢救与回忆进入结局文字。

作者路线：拆信 → 新邮戳 → 合照（可选）→ 档案室 → 漏水桌面 → 抢救一种证据 → 蓝色铁盒 → 联系证据作出判断 → 返回值班室 → 投递或珍藏。4 余力/段，共 4 段时间，阅读队列需确认后继续。

8 条选择组合对应 6 个主动结局文本变体，另有未完成的超时结局。规则测试覆盖重新判断、互斥持有、未知地点隐藏、历史记录与超时；`node scripts/publish_solo_story.mjs` 发布新版本并用实际 HTTP 单人身份验证 8 条路线。本地管理员凭据位于忽略的 `.local/admin-review.json`。已有同名剧目时仅在内容变化时发布新版本。
