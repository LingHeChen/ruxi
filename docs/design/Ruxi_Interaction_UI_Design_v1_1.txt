入戏交互与 UI 设计
类 Apple 的简洁界面与连续动态交互
版本 1.1  |  2026 年 10 月 8 日  |  对应产品 2.0 与技术 1.0  |  统一修订 C1
本文件独立定义入戏多人互动剧的视觉和交互规格。设计方向由用户明确提出：类 Apple 风格、简洁主义、微交互、丰富且平滑的转场、自适应布局，以及布局变化本身的动画。这里的“丰富”落实为各类状态变化都有清晰、连续的反馈，而不是增加持续运动的装饰。
基线场景为三名玩家分别扮演调查员、乘客、乘务员，观看剧情、获取私有线索、交付道具并共同投票。玩法及房间时限以产品文档 2.0 为准，服务端状态和信息授权以技术文档 1.0 为准。本文件补充表现、操作和验收，并附组件状态示意图、关键页面构图和离线 HTML 行为样例。视觉与规则共同构成开发输入；HTML 不包含真实视频、服务器或多人同步。

发现、详情、大厅和设置跟随系统明暗模式；剧情舞台默认采用深色沉浸背景，线索阅读支持浅色纸面模式。模式切换只对色彩和表面做约 180ms 过渡，不重新播放页面进入动画。浅色主按钮使用深琥珀底配白字；深色使用浅琥珀底配深字，不能直接把浅琥珀当白底小字。
玻璃只用于覆盖在内容之上的导航或短时浮层，正文阅读面板使用近乎不透明表面。字幕和角色秘密不可因背景视频明暗变化而难读。大面积模糊默认关闭；低性能模式和减少透明度偏好用实色替代。
字体 间距与形状
使用平台系统字体和适合中文的系统回退字体，不随安装包分发未经许可的 Apple 字体。文字层级建议：页面标题 28/34、分区标题 20/26、正文 16/24、辅助 14/20、标签 12/16，前者字号后者行高，单位为逻辑像素，最终跟随系统文字缩放。12 号字不承载关键剧情或错误。
间距使用 4、8、12、16、24、32；手机水平页边距 20，紧凑屏可降至 16；卡片内距 16—20。卡片圆角 20、按钮 14、面板顶角 28 作为基准，连续圆角由统一组件实现。阴影仅用于层级和悬浮，不给每张卡片叠加浓重投影。交互目标最小 48×48，图标可为 20—24，但命中区独立扩大。
2 导航与交互原则
全局一级导航为“发现”和“我的”，活动房间通过固定的“返回房间”入口恢复。进入房间后界面围绕当前阶段展开，不保留与玩法无关的底部导航占空间。探索、线索、讨论是房间内部切换，不创建新的业务房间或重连 socket。
用户触碰立即获得视觉反馈；公开、交付、投票等业务结果等服务端确认后再显示完成。动画开始不表示请求成功。成功状态不能因重复回执重播，失败后恢复到可重试状态并解释原因。
每屏只强调一个当前主要操作。次要操作使用低对比按钮或菜单；返回和关闭位置稳定。复杂规则放在需要时出现的说明中，例如第一次公开线索时说明不可撤回，而不是初次进入时展示整页说明。
返回和手势优先级
系统返回依次关闭菜单、关闭线索详情、收起展开面板，再回到房间大厅或剧集详情。正在进行的局离开页面不等于主动退出；主动退出使用独立菜单和确认，说明结算前退出会挂起本局；结局阶段只离开页面。横向拖动视频不默认切换剧情；下拉面板只在标题把手或正文已滚到顶部时接管，避免与阅读滚动争抢。
用户拖拽时面板直接跟手，不先做固定时长动画；松手后再按速度和位置决定吸附。手势取消回到最近稳定位置。公开线索、转移物品、结束探索这些业务操作不绑定容易误触的滑动捷径。

超宽屏设置主要工作区最大宽度 1440，留白用于呼吸感，不无限拉宽文本。正文阅读宽度建议不超过 680。折叠屏可用区域分开处理，文本与关键按钮不能落在铰链遮挡处。播放器维持素材比例，人物主体不为铺满屏幕而裁掉。
从底部面板到侧栏的过渡
跨断点时保持当前任务、选中线索、滚动位置和输入草稿；线索面板从底部扩展为右侧工作栏，舞台同步缩小并重新居中。建议 280—360ms，以快起慢停的曲线衔接。保持标题和已选线索的空间关联，不让所有元素先消失再突然出现。
窗口持续拖动时宽高直接追随 constraints，避免每帧重新启动 300ms 动画造成拖尾。结构跨阈值才执行一次过渡；断点附近使用小幅滞回或短时去抖避免反复切换，但不能强行撑出视口。系统旋转造成不可插值的约束变化时可用短淡化配合位置连续，不承诺所有平台都是同一种转场。
4 页面规格与关键状态
发现与剧集详情
发现页顶部标题与短引导，第一屏展示继续中的房间及一张精选剧目卡；封面明确人数和时长。首版一部样片也保持真实内容密度，不用虚构排行榜填充。点封面进入详情，封面与标题保持连续位置关系，内容区轻微上移与淡入。返回时恢复列表原位置。
详情页显示封面、三人标识、10—15 分钟预计时长、无剧透简介和角色简介。主按钮“创建房间”，次按钮“输入邀请码”；已有活动房间时主按钮变“返回房间”。加载失败就地显示错误与重试；不把错误呈现为无限骨架屏。
房间大厅
顶部显示剧名、邀请码和复制操作；中部三张角色卡明确头像、角色名、已选玩家与准备状态。选择角色后卡片边界、选中标识和小幅位移共同反馈；其他人的选择由服务端事件更新，不抢走本人的操作焦点。角色被抢先选走时保留当前页面，提示改选。
底部固定“准备”或“取消准备”；房主另有“开始”，但未全员准备时禁用并说明缺谁。准备状态以复选标识和文字呈现；在线状态不靠闪烁呼吸灯。复制邀请码给短 toast 和可选轻触觉，不弹阻断对话框。
剧情舞台与探索
顶部轻量状态栏包含返回、阶段名、三位成员状态；中间是视频或场景，字幕置于有足够对比的底部背景上；下方为当前目标和活动面板。观看时面板收拢，探索阶段自然展开而非整页切换。计时只在确实有截止时间的阶段显示。
探索面板使用“场景 / 线索 / 讨论”分段切换；切换保留各自滚动位置。我的线索和共享线索分别有文字标签；未发现线索不显示泄密名称或数量变化。新线索到达只在本人面板出现一次轻提示，其他玩家界面不得出现暗示秘密行动的动画。
线索详情与交付
线索卡展开为阅读面板，标题、封面与正文有连续转场；来源与“仅你可见 / 已共享”明确显示。公开按钮旁写清公开范围，确认页展示即将公开的线索名称及“所有成员可见，无法撤回”；授权视图事件应用后标签变为共享并更新公共面板。
交付道具先选接收人再确认。发起人看到“等待对方接受”及取消/过期状态；接收人看到一张可接受或拒绝的邀请卡。不得让道具先飞进接收者背包再等待服务器。只有事务成功后双方各自在自己的可见界面做一次位置或状态过渡；不向第三人播放包含私有物品名称的动效。
投票与结局
决策面板展示问题、2—3 个候选、剩余时间和“我的选择”。选中项立即给按压反馈，但只有回执确认后显示已提交标识；改票仍要显示等待状态。倒计时最后十秒可以增强文字对比，不连续震动或缩放。其他人的具体票型在截止前不可见，不能用按钮高亮暗示。
结算时短暂禁用操作并显示“正在公布结果”，随后显示汇总和对应视频；超过三秒则给同步说明，不制造无限悬念动画。结局页展示结局卡、已公开事件与自己的经历，未公开的他人秘密不进入复盘。主操作“再来一局”创建新路线，次操作“返回剧集”。

阻尼弹簧只用于可操控表面、卡片和面板，过冲应轻微；正文、字幕和倒计时不弹跳。相邻控件的小幅顺序进入可间隔 20—35ms，总展开时长不得因此拖长到一秒。任何循环动效都必须有明确等待语义，场景背景不持续漂浮。
状态变化与业务反馈的分离
点击投票的按压反馈本地立即执行；“已提交”跟随服务器回执；结局转场跟随服务端结算事件。这是三个不同触发点。相同 event_id 或 view_seq 的重复消息不能再次播放成功动效。快照恢复只平稳恢复当前状态，不重演玩家断线期间全部动画。

7 自适应过渡中的状态连续性
屏幕变宽时，把当前线索从底部面板迁至侧栏，选中线索 ID、阅读位置、文本选择和未发送聊天草稿全部保留。视频 controller 与房间连接的生命周期位于布局容器之上，不能因为窄屏 Widget 换成宽屏 Widget 就重新开播或再次 join。
为每个内容对象使用稳定 key；结构变化由一个 LayoutCoordinator 决定目标布局。普通尺寸和间距变化用隐式动画；手势驱动、多个元素协调和可反向过渡使用显式 controller。AnimatedSwitcher 适合内容替换，但不能同时挂载两个活跃播放器或重复建立带副作用的子树。共享封面可以用 Hero，活跃视频表面使用稳定宿主或静态快照过渡。
键盘出现使用实际 viewInsets 与布局约束，只调整需要避让的区域，避免键盘自身动画和自定义补间叠加。用户开始打字时把讨论输入和最近消息保持在可见区；收键盘后恢复此前面板高度，不重置探索面板。
动态效果偏好与降级
提供“跟随系统 / 减少动态效果”设置。减少动态效果下取消大范围缩放、视差和弹簧过冲，面板与页面以直接布局加短淡化表达；拖拽仍跟手。触觉可关闭，不能是唯一成功信号。关闭透明效果时仍保留层级。进入后台时暂停不可见动画，回前台不补播旧动效。

Flutter 官方将自适应与响应式区分为可用布局选择和随空间调整；隐式动画允许通过目标值、时长和曲线驱动属性变化。[U1][U2] 本文断点、时长与组件组合均为项目设计，不是框架自动保证。依赖版本与具体 API 在实现时锁定验证。
业务事件只改变目标 UI 状态，动画协调器负责如何到达该状态。快速连续输入时重定向当前动画，而不是排队播放旧目标。释放 controller、ticker 和监听器；重连后的 snapshot 属于状态替换，不触发所有 new/成功动画。玩家私有字段不得进入公共 Hero tag、调试标签、截图遥测或全局动画消息。
9 无障碍与质量验收
文字与背景对比由工具检查；普通文字以至少 4.5:1、大字至少 3:1 为设计验收目标，控件边界和焦点可辨。字体放大至 200% 时核心任务仍可操作；关键文案换行，不用省略号藏掉选项差异。语义顺序跟随当前布局，响应式重排后键盘焦点仍回到同一内容对象。

17 统一交互补充
回执与可见事实
本地按压立即反馈；committed 回执仅显示“已提交”。receipt_seq 尚未应用时显示“正在同步”，不得提前移动道具、改共享标签或改已确认票型；视图事件原子应用后播放一次成功动效。事件先于回执到达时也只播放一次。原 HTML 的 750ms 模拟回调代表回执和视图同时到达，不能作为真实网络 reducer。
换角与暂停
大厅已选角色卡新增“请求交换”。对方看到双方公开角色名、接受、拒绝和 30 秒剩余时间，发起方可取消。等待期间双方不能准备或开始；原子交换事件到达后两人取消准备。离开、角色变化或过期会取消请求；不做先释放再抢角色。主动暂停入口只对房主启用，其他成员收到 30 秒确认提示；无人强制暂停。
锁定候选与媒体
VoteOption 增加 locked 状态，只读服务端 display_options 的 label、eligible、reason_code 和 reason_text。未授权时显示“需公开关键证据”，不得显示 C3 名称。中场显示“探索结束”，关闭行动和提示，播放公共片段并等待队友完成；五分钟仍未完成显示已保存待恢复。ending 允许离开阅读，不因其他人掉线卡住结算。
身份与演示边界
游客首次登录提供恢复码保存入口及不可找回说明；恢复页输入恢复码，成功后重新同步原席位。后台登录页输入部署管理员提供的一次性码，不提供游客升权按钮。现有图稿和 HTML 仍是视觉参考，未演示换角、身份恢复和中场流程；它们须按本节补做 Flutter 页面及 QA31—QA34 验证，不能标为已实现。
