入戏多人互动剧数据设计
关系模型  数据字典  事务一致性  私有视图
版本 1.0  |  2026 年 10 月 8 日  |  对应产品 2.0 与技术 1.0  |  统一修订 C1
本文件面向 Flutter 客户端、Elixir 核心服务和 Python 任务服务的实现者，定义入戏三人协作样片的数据边界、字段、约束、索引与生命周期。它将技术文档中的表级草案细化为可评审的数据方案，覆盖建房、选角、调查、共享、道具交付、投票、提示和中断恢复。
数据库采用 PostgreSQL；只有 Elixir 核心服务可以变更游戏事实。视频、音频、字幕文件存对象存储；数据库保存元数据和授权依据。Flutter 保存的是当前成员的可见缓存，Python 接收的是任务授权输入，两者都不拥有完整房间的裁定权。
设计决策
本版确定方案
事实与快照
结构化列负责可约束、可查询的事实；state_json 负责小型剧情状态及同事务生成的恢复缓存。
身份与权限
账号、房间席位、角色、控制设备分别建模；房主身份不增加信息权限。
事件与通知
内部事件只供核心服务审计；每成员拥有独立连续的可见事件流。
幂等与并发
命令回执、唯一键、room 行锁共同保证业务效果最多一次；推送仍为至少一次。
内容冻结
房间引用不可变内容版本；发布不修改已有版本，旧房间不自动迁移剧本。
实现程度
本文是逻辑与物理设计基线，含 SQL 片段和验收用例；尚未执行迁移、并发测试或恢复演练。

主键使用服务端生成的 UUID；客户端生成协议规定的设备、幂等请求及埋点 ID，服务端仍校验格式与作用域。时间统一 timestamptz，以 UTC 存储；展示时转换本地时区。时长为 bigint 毫秒，不能用浮点秒保存截止依据。JSON 字段有独立 schema_version，未知字段默认拒绝或不投影。简写字段中 *_id 与 created_by 为 UUID，*_at 与 *_until 为 timestamptz，*_hash、状态、名称和正文为 text；其他类型另行标注。
字典中的 ? 表示可空，未标注者为 NOT NULL；id 默认 UUID PK；所有实体带 created_at，可变实体另带 updated_at。计数和代次为非负 bigint，状态使用 text 加命名 CHECK。JSON 默认空对象或空数组只用于确实允许空值的字段，不能掩盖缺失的必填数据。
member_id 是物理字段名，协议中的 membership_id 是同一身份；revision 对应技术文档的 room_revision。items / offers 在本版定名 room_items / item_offers。命名映射不改变既有协议语义。
约束层次
数据库负责主键、外键、非空、唯一、行内范围和枚举；服务事务负责人数、角色是否属于版本、阶段合法性及信息权限。跨行规则不能伪装成 CHECK；跨表引用可用外键时优先外键。PostgreSQL 外键不会自动为引用侧建立索引，按查询与删除路径补齐。[D1]

每次有效业务变更在同一事务内更新结构化表、state_json、revision、内部事件、成员视图事件与 outbox。state_json 禁止其他服务直接改写。恢复读取当前事务快照，不依赖把历史事件全部重放；本版不采用完整事件溯源。
所有引用席位的房间子表使用复合外键 (room_id, member_id) → room_members(room_id,id)，父表增加 UNIQUE(room_id,id)。物品、轮次也提供同样的复合唯一键；不能只验证 member_id 存在却允许跨房间引用。
3 剧目与不可变内容版本
stories 与 content_versions
字段与类型
约束与含义
stories.id / slug text
slug 唯一；展示目录的稳定身份。
title text / summary text
只存无剧透的目录摘要；封面关联公开资产。
current_version_id uuid?
新房间默认版本；发布事务校验该版本属于同 story。
content_versions.id / story_id uuid
story_id FK；UNIQUE(story_id,version_no)。
version_no integer / schema_version integer
正整数；内容迭代与内容格式迭代分开。
status text / revision bigint
draft、approved、published；草稿修改递增 revision。
graph jsonb / content_hash text
包含角色、阶段、行动、线索、媒体引用、结局和固定提示；规范化后 SHA-256。
seat_count smallint
CHECK 2—4；样片固定 3，必须与 graph 角色数一致。
approved_hash text? / approved_by uuid?
审批绑定确切内容 hash；草稿变更清空审批。
published_at timestamptz?
published 后 graph/hash/版本号不可变；撤回销售用独立 availability。
availability text / blocked_reason text?
available、unlisted、blocked；blocked 是安全运营动作，不修改剧情图。
content_hash 覆盖 graph 及引用资产的内容摘要，不包含签名 URL。发布事务检查全部资产 ready、审批 hash 匹配、角色与超时路径有效，再冻结并更新 stories.current_version_id；审计记录同事务写入。数据库写权限只授予发布入口，冻结字段另用 UPDATE 触发器保护。
最小 graph 顶层：schema_version、roles[]、phases[]、actions[]、clues[]、endings[]、media[]、hints[]。每个节点有版本内稳定 code；scope 只允许 public 或 role，加 role_code。完整 graph 含谜底，不作为普通客户端可下载的配置包。
新版本撤回后仅改变新开局默认版本；旧房间保留原 content_version_id。被引用版本禁止硬删除。紧急 blocked 时经 RoomStore 将相关尚未结算活动房间挂起并发安全公告，后台不得直接替换房间剧本。
4 房间及持久化时钟
rooms
字段与类型
约束与含义
id / content_version_id uuid
版本 FK，删除 RESTRICT；创建即绑定发布版本。
lifecycle text / phase_code text?
lobby、running、paused、suspended、finished、abandoned；阶段 briefing / exploration / decision / ending。
phase_id uuid? / phase_epoch bigint
每次进入新阶段生成 ID；暂停恢复不更换。大厅无 phase_id。
revision bigint / state_schema_version integer
revision 每个业务变更事务加一；只服务端可见。
state_json jsonb
剧情权威字段与恢复缓存；初始软预算 256 KiB，越限报警并阻止内容发布扩大状态。
host_member_id uuid? / locked_at timestamptz?
host 复合 FK 指向本房成员；locked_at 后席位和角色不变。
deadline_at timestamptz? / remaining_ms bigint?
阶段计时唯一权威；暂停清空 deadline，保留非负剩余时长。
timer_generation bigint / lifecycle_deadline_at timestamptz?
阶段定时器代次；生命周期截止负责暂停 5min、挂起 24h 和大厅空闲。
owner_instance text? / owner_epoch bigint
后端进程持有者及栅栏代次；与产品房主不同。
lease_until timestamptz? / finished_at timestamptz?
租约期限；终态时间用于保留期起点。
last_activity_at timestamptz / suspension_reason text?
有效大厅操作刷新空闲时间；挂起记录原因。
统一使用 rooms.deadline_at 裁定当前阶段。vote_rounds 不另存一个可独立修改的 deadline；读取轮次截止需联接 rooms。对应技术 1.0 的轮次 deadline_at 是读模型字段。历史截止变化写入内部事件，结算保存最终截止。这样暂停恢复不会出现两套时间。
取得 room 行锁后调用 clock_timestamp() 获取决策时间；CURRENT_TIMESTAMP / now() 是事务开始时间，不能让等待锁的迟到投票获得旧时间。[D2] 若 deadline 已过，先执行一次截止，再处理新命令。终态清空运行定时字段。

6 账号 邀请及入口幂等
身份与短期凭证
字段与类型
约束与含义
users：id, display_name, status
status active / disabled / erased；擦除账号保留墓碑 ID，不能重用。
auth_identities：id, user_id, provider, subject
UNIQUE(provider,subject)；第三方主体标识不在房间事件输出。
devices：id, user_id, revoked_at?
设备 ID 不是凭证；与当前登录用户绑定。
sessions：id, user_id, device_id, refresh_hash
加 expires_at、revoked_at?；只存高熵 token 的哈希，轮换时撤销旧 token。
socket_tickets：id, token_hash, room_id, member_id
加 device_id、control_generation、expires_at、consumed_at?；60 秒、一次性条件 UPDATE 消费。
room_invites：id, room_id, code_hash, key_version
加 expires_at、revoked_at?、created_by；默认 24h，开局或大厅关闭即失效。短码用带服务端密钥的 HMAC，不能仅普通 hash。
邀请码熵有限，必须限流、校验有效期和人数，不能当作房间内身份。保持 code_hash 在保留期间唯一；实际码通过安全随机生成，碰撞重试。邀请码只允许进入大厅，开始后的恢复通过原 user/member 身份，不通过邀请码占用新席位。
account_commands
字段与类型
约束与含义
user_id uuid / operation text / command_id uuid
复合 PK；覆盖 room.create、room.join、room.takeover、invite.rotate 及 admin 业务 POST；operation 命名以接口为准。
payload_hash text / response_json jsonb
同 ID 同摘要返回原结果；不同摘要拒绝。

7 剧情状态与玩家知情记录
首版每房 2—4 人、线索数量有限，知情记录随 state_json 保存，避免为每个剧情布尔变量新建表；需要跨房统计时由事件异步提取。道具所有权仍在独立表，不能藏进 JSON 当作唯一依据。
{
  "schema_version": 1,
  "world": {
    "discovered": {"member-A": ["C1"], "member-B": ["C2"]},
    "shared_clues": ["C1"],
    "action_claims": ["member-A:camera", "member-B:phone"],
    "flags": {"cabinet_open": false}
  },
  "knowledge": {
    "member-A": {"clue_codes": ["C1"], "media_codes": []},
    "member-B": {"clue_codes": ["C1", "C2"]},
    "member-C": {"clue_codes": ["C1"]}
  },
  "progress": {"early_finish_acks": []},
  "cache": {"revision": 12, "round": null,
    "items": [{"item_code": "C2",
      "owner_member_id": "member-B", "version": 1}]}

例中 member-A 等是可读占位符，正式使用 UUID。线索描述来自固定内容版本；状态只存 code，避免每次改变状态都复制大段私有文本。公开 C1 时同时更新共享集合与全体知情集合。C2 被接收后给接收者增加知情记录，原持有者的知识不删除；是否能使用 C2 只看 room_items.owner_member_id。
字段
去重与校验
action_claims
以成员 + 行动 code 唯一，房间锁事务检查；重复调查不再次发物品。
shared_clues
只增不减；验证发起者知情且允许公开；未知 code 拒绝。
knowledge
只由 Rules 改变；对外生成本人子集，不输出所有成员的映射。
flags
只允许版本 schema 已声明字段；发布阻止任意表达式执行。
cache.revision
必须等于 rooms.revision；不一致停止响应变更、重建缓存并报警。
snapshot API 不返回以上原始 JSON。它返回 Projector 的 public_scene、own_role、own_clues、visible_items、available_actions、own_vote、members 等接口第 9 节模型 和 base_seq；绝不包含 cache.revision 或完整条件表达式。
8 道具与双向交付
room_items
字段与类型
约束与含义
id / room_id uuid / item_code text
UNIQUE(room_id,item_code)；样片每种物品只有一份。
owner_member_id uuid / version bigint

owned / consumed；本版无落地拾取和堆叠数量。消耗后仍保留原归属用于审计。
item_offers
字段与类型
约束与含义
id / room_id uuid / item_id uuid
FK(room_id,item_id)；每个物品至多一个 pending offer。
from_member_id / to_member_id uuid
均为本房成员；CHECK from <> to。
phase_id uuid / expected_item_version bigint
请求绑定发起阶段和物品版本；不绑定全房 revision。
status text / expires_at timestamptz
pending、accepted、rejected、cancelled、expired；默认 30 秒。
resolved_at timestamptz? / reason text?
终态写入实际时间；暂停、阶段变化等取消记录明确原因。
CREATE UNIQUE INDEX one_pending_offer
  ON item_offers(item_id) WHERE status = 'pending';
CREATE INDEX offers_due
  ON item_offers(expires_at, id) WHERE status = 'pending';
pending 本身就是交付锁，不另存容易失配的 item.locked 布尔值。发起时锁 room→item，检查归属、版本、接收者在线且同阶段；插入 offer 后所有权不变。接受时锁 room→item→offer，再取当前时间；若已过期先标 expired，不允许“最后一次点击”绕过截止。
成功接受同事务修改唯一 owner_member_id、递增 item.version、offer=accepted、接收者知情集合、两人的投影与回执。拒绝、取消或到期不增加物品版本；新 offer_id 区分新一轮邀请。暂停或阶段切换先关闭 pending offers；后台扫描只挑候选 ID，再按统一锁序执行，不先锁 offer 再锁 room。
9 投票 选民与唯一结算
vote_rounds 与 vote_electorate
字段与类型
约束与含义
vote_rounds.id / room_id uuid / phase_id uuid
UNIQUE(room_id,phase_id)；一个决策阶段一轮投票。
status text / options_json jsonb

约束与含义

17 数据迁移与恢复
场景
执行规则
新增字段
先允许旧版本读取的可空/默认字段；部署兼容读写，再分批回填、验证约束，最后收紧。
重命名或拆字段
先读旧写新或双写；监测差异、回填；所有客户端兼容后移除旧字段。
state_schema_version 升级
纯函数逐版 upcast；锁 room 后转换并原子提交；保留原快照备份和转换记录。
事件协议升级
内部 schema_version 与公开 protocol_version 独立；补发保留历史解释器或改走新快照。
剧目升级
新 content_version，旧房间继续旧版；不把数据库 schema 迁移等同于改剧本。
索引与大表变更
先测锁时长和计划；在线索引单独迁移；失败后检查残留，不盲目自动重跑。
一版迁移包含 up、可行的 rollback、兼容窗口、数据校验和失败中断点。删除列、改语义、擦除数据不能靠 down 脚本恢复，先备份再执行。建议 first migrations 顺序：账号与内容 → rooms/members → 子表与复合 FK → outbox/任务 → 索引与权限。rooms.host_member_id 的循环依赖在建完成员表后添加可延迟 FK。
备份和恢复目标
上线试运行目标 RPO≤5 分钟、RTO≤60 分钟，均为待演练目标。采用加密基线备份和连续 WAL 归档，PITR 的恢复范围取决于完整基线及其所需 WAL；仅有每天逻辑导出不满足该目标。[D4] 建议基线备份每日、连续归档、保留 14 天，并为资产启用独立版本/备份策略。
恢复先在隔离环境：还原 DB 与资产引用；重放擦除清单；撤销所有会话和票据；使 room owner、worker、outbox 旧租约失效；尚未结算活动房间转 suspended；ending 房间保留已结算事实并按截止转 finished；核对快照与子表、结算、对象 hash；最后原成员重新认证恢复。不能把旧备份中的 lease_token 继续当有效。
从备份回滚可能丢失曾已回复成功的最新事务，必须明确 RPO 的用户影响。灾难恢复切换服务级 recovery_epoch，旧客户端缓存失效并强制全量快照；epoch 由恢复控制面生成，不能从回退的备份复用。正常重连不需要此字段变化。每月至少演练一次恢复并记录真实耗时。

分析数据不阻塞玩法

决策与原因
内容与事件版本演进
现在实现版本边界。历史数据和客户端协议迁移代价高，后补不只是机械重构。

商业化与多租户

19 协作与投影数据补充
原子换角的状态
state_json.progress.role_swap 为 null 或 {id,from_member_id,to_member_id,from_role_code,to_role_code,status,expires_at}，ID 为 UUID，status 为 pending/accepted/rejected/cancelled/expired。每房至多一个 pending，30 秒到期；两人须在 lobby、在线且已选不同角色。接受时锁 room→两 member（ID 排序），复核双方角色与请求一致、未过期，再原子交换并取消双方 ready。选角、退出或断线使涉及的请求 cancelled；ready=true 和 start 遇 pending 返回 NOT_ALLOWED。
媒体进度与唯一时钟
progress.exploration_step=active/interlude，仅 exploration 存在；中场确认用 progress.interlude_acks 成员集合。active 截止变更为 interlude 五分钟截止，rooms.timer_generation 增长；全员确认进入 decision。中场截止后 suspended，remaining_ms=300000 供恢复，不能恢复即再次过期。ending 使用 rooms.deadline_at 五分钟不可暂停窗口；普通断线及退出不得改为 suspended。
冻结投票展示
vote_rounds.options_json 仍只保存可投集合；新增 display_options_json jsonb，冻结安全展示对象 {option_id,label,eligible,reason_code?,reason_text?}。eligible=true 的 ID 集合必须严格等于 options_json；disabled 文案来自内容版本显式 public 展示文本，不直接序列化条件表达式。发布校验默认与平票优先序覆盖可投集合。
任务回执及数值
work_items 新增 result_json jsonb? 与 completion_response_json jsonb?、completed_attempt integer?，存 accepted/ignored 最终回执并保留 result_hash。result_ref 可继续指向输出对象，不能取代 tagged union；完成回执按 job/attempt 去重。公开 seq、generation、version 输出前检查≤2^53−1；内部存 bigint。graph.schema_version=2；state_json.schema_version 与 rooms.state_schema_version 为 1。

20 认证与后台幂等数据补充
游客恢复
users 增 recovery_code_hash text?（唯一非空索引）、recovery_generation bigint。首次游客创建生成 256 位随机恢复码，仅一次展示，数据库存摘要。恢复锁 user，校验码、轮换新码并撤销该 user 所有旧会话/票据，创建新设备会话；新码与凭证的 60 秒重试响应加密保存。日志不记录码。恢复点中不存在的 user 无法恢复；无凭证又无恢复码不能按设备 ID 找回。
后台身份
admin_roles(user_id uuid FK, role text)，联合 PK，role∈editor/reviewer/publisher。admin_login_codes(id uuid PK,user_id uuid FK,token_hash text UNIQUE,expires_at,consumed_at?)，五分钟单次有效，仅部署 CLI 可生成或撤销；CLI 指定已有受控 user，不能接受游客自行申请。部署操作者留审计身份。sessions 增 audience=player/admin、family_id uuid、绝对 expires_at；admin refresh 最长 8 小时，access 最长 15 分钟。
轮换与请求重试
sessions 之外增加 auth_refresh_tokens(id,family_id,token_hash UNIQUE,expires_at,consumed_at?,revoked_at?)，轮换保留已消费 hash 以识别重放。auth_retry_cache(scope,key_hash PK,request_hash,response_ciphertext,expires_at) 保存 guest.create / guest.recover / admin.exchange / auth.refresh 的 60 秒加密响应；scope 包含相应请求 ID、码/token 摘要及设备。同键异参拒绝，过期清理，非明文凭证长存。
后台业务幂等
account_commands 覆盖所有 admin 业务 POST，operation 为接口附录的固定名称，payload_hash 包含路径目标 ID 与正文，默认保留 30 天。PUT 草稿使用 revision 条件更新，成功后重发旧 revision 返回 REVISION_CONFLICT，客户端 GET 查证，不承诺重复成功。账号前置锁→内容行/资产行；不得在持 room 锁后反向锁账号。上传意图重试返回原资产与原链接，链接过期须新 command_id 申请新意图。
灾难恢复与凭证
灾难恢复撤销会话、一次性登录码、票据及重试缓存；保留恢复点内 user 的恢复码摘要，原玩家用恢复码重新认证。部署管理员重新签发后台登录码。恢复点之后创建或轮换的恢复码可能无效，作为 RPO 数据损失告知，不伪造身份自动接管。
pause_request 增 requested_by_member_id，创建时确认集合包含发起者；房主转移或探索转中场取消。media_epoch 按授权片段存于 progress.media_epochs[usage_code]，公共锚引用同一值；所有确认集合按 media_id 与 media_epoch 绑定，不能确认旧锚。后台业务幂等记录可存资源标识，任何临时签名URL必须加密保存；日志不记录完整地址。
