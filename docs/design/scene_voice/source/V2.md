# 入戏场景语音技术设计

## 1 技术边界与决策
Flutter 接入 volc_engine_rtc，Elixir 继续作为位置、成员资格和房间时序的唯一权威；音频直接经火山 RTC，WS 只传状态与控制。Python 不代理真人音频，不启动 AI 对话任务。本设计不新增音视频微服务、消息队列产品或自建 SFU。
建立 Flutter SceneVoiceController 与 VolcRtcClient 模块，服务端 VoiceCoordinator 与 VolcRtcGateway 模块。前者处理产品状态，后者封装供应商 SDK、签名与房间封禁。服务端允许内部凭证含 provider 专有字段，但外部游戏状态不依赖其 ID 格式。
变化隔离决策为 IMPLEMENT_NOW：供应商可能因报价或 SDK 支持改变，直接散布接口会影响 UI、鉴权、审计及持久身份，这部分迁移成本高。只增加两个薄模块边界，约 6 个操作；DEFER 多供应商注册表和运行时工厂，后续内部重构较容易。禁止为此复制现有房间模型或再做一套账号系统。
参考 figures/architecture.mmd 为结构图，figures/scene-switch.mmd 为换场景顺序。客户端 API 具体签名以锁定版本的 Flutter SDK 为准，不能把 Android 示例直接复制到 Dart；依赖锁定及两台真机测试是 V4 发布门槛。
## 2 身份与凭证
游戏 room_id、member_id 与 RTC room_id、uid 分离。逻辑语音频道为本局加场景；物理 RTC 房间为频道加 generation 映射的随机标识。RTC UID 每次新授权随机生成，服务端表关联本局成员、控制设备、control_epoch 和授权编号，不携带名称、阵营或密室 ID。
Token 服务端生成并绑定 AppID、物理房间和 RTC UID，禁止使用通配房间 Token；密钥仅在密钥管理或服务端环境。Token 有效期 120 秒，授权租约 30 秒；租约靠每 10 秒心跳延长，客户端在 Token 剩余 45 秒时申请更新。续签必须验证当前控制权、场景、频道代数、未禁用和租约，不能只验证旧 Token。
Token 不是独立的即时撤权机制。每次收回资格必须封禁旧物理房间，并防止旧凭证重新进入；短有效期仅缩小故障窗口。RTC 返回加入成功才表示 connected，WS 通知只表示授权状态。Token 只经 authenticated HTTPS no-store 响应返回，不进入 WS outbox、日志、URL、浏览器缓存或持久数据库。
## 3 频道与租约状态机
逻辑频道状态为 dormant、opening、active、retiring、blocked。dormant 表示无需 RTC；opening 是新代数可申请授权；active 有有效加入；retiring 禁止新授权且正在回收；blocked 表示无法确认回收。房间重建用 generation 单调递增，永不复用被封禁物理房间号。
成员参与意愿 participation=off/on 与连接状态独立。租约状态为 issued、connected、revoking、closed、expired；有效集合是 issued/connected 且未过期。不能因尚无 SDK 加入回调就忽略已经发出的有效凭证，回收必须包括已发未用的授权。
只有当前合格、选择参与的成员数不少于 2 时才分配频道。首次两人连接可仅 opening 一次；已 active 后添加、移除成员或收回资格都重建该场景代数，避免旧成员继续监听新会话。代价是同场景其他人短暂重连并关麦，此为本版明确取舍。普通本地关麦、调音量和屏蔽别人不重建频道。
单设备控制沿用现有 control_epoch。换设备前旧授权须回收，新设备在 fencing 完成前只能读游戏状态。后台、登出、租约过期、运营暂停资格和房间结束均走同一回收路径。租约过期检测周期 5 秒；不能依靠本机 leave 成功充当服务端安全证据。
## 4 场景切换与世界结算
世界移动仍使用 C3 的步结算、AP 预留与原子 group_move。增加结算准备阶段：冻结本步输入并持久化 execution_id 与结算计划，计算哪些玩家将改变场景或失去资格，收集涉及的旧语音频道。计划使用同一随机 journal，重试不重新掷骰。不能只为 move 命令处理，传送、退房、控制权变化也必须覆盖。
在提交世界位置变化前，将受影响频道标记 retiring，停止签发和续签；向现有成员私有流发送静音并重连状态；客户端立即停采集停播放。服务端调用 BanRoomUser，指定 AppId、旧 RoomId，不指定 UserId，ForbiddenInterval=180，踢出并限时关闭整间旧语音房。此封禁期覆盖所有已发 Token 剩余有效期和 30 秒时钟裕量；旧房号永久不用，因此封禁到期也无新授权。
所有受影响旧频道回收成功后，按 V4 验证的供应商传播语义记录 fence_complete，才把世界动作、AP、到达事件、成员投影和新语音代数在同一事务提交。提交后新授权按最新场景生成，尚未回收成功绝不先显示移动到达或发新凭证。团体移动一次性冻结成员集合、回收相关频道，再原子提交，不逐个先行到达。
第三方回收与数据库不可能成为同一个原子事务，采用持久工作流：计划已存但尚未封禁时可重试；封禁成功而数据库未提交时旧世界不变，恢复同一计划；世界事务失败后若放弃原计划，必须在旧世界状态下开新代数，不能重新启用被封禁房间。AP 只在世界事务执行时扣除，RTC 故障不算剧情失败。
调用超时不能当作成功。8 秒未完成回收，冻结受影响的整个步结算并暂停游戏时钟，显示“正在安全切换”，不泄露目的地；运维重试同一任务。确认所有旧会话关闭后可关闭本局语音并继续原计划，不能仅关闭 UI 就解除冻结。供应商全局故障时，只有已验证的 Token 到期强制离房语义可作为备用收口证据；若未验证，继续挂起，不伪称安全降级。
网络缓存可能留有撤权前采集的尾音，不能承诺物理上零毫秒。上线须实测 API 成功、媒体停止与旧 Token 重入的关系；若 API 成功不代表媒体撤销已生效，适配器需等待供应商可验证完成条件，未具备条件不得开放强隔离语音。正常目标为新场景音频不向旧成员下发；撤权前尾音单独测量和记录，不把固定 sleep 当安全证明。
## 5 协调器与并发恢复
每局 VoiceCoordinator 跟随现有房间 owner_epoch，持久事务采用 fencing 检查。旧 owner 不能签发租约或推进世界计划。外部封禁由 outbox 工作者执行，重复封禁同一旧房是安全重试；新代数不得复用旧房号，迟到调用无法误封新房。
外部操作完成后数据库以任务 ID、owner_epoch 与目标 generation 做 CAS；旧回调只记审计，不覆盖当前状态。所有路径采用同一锁序：room、channel 按 ID 排序、member。UI 的连续点击、HTTP 重试、掉线回调均以 request_id 和 revision 去重。
服务端 SDK 回调仅用于对账和异常检测，不决定玩家位置或授予权限。生产开启回调前须按锁定的官方签名协议验签、去重、防重放；字段未核实前不自造签名算法。回调不可用时不影响业务鉴权，回收证据仍须满足上一节，不能由不可信客户端 reported_left 替代。
服务端宕机恢复先重放未完结 retirement 与已冻结的结算计划，再允许新授权。未知供应商状态的频道按 blocked 处理，不乐观恢复。没有被房间 owner 接管确认的旧租约不得续期；游戏存档不保存可重新使用的 RTC Token。
## 6 Flutter 音频与生命周期
SceneVoiceController 串行管理 SDK 实例；物理房间切换先停止发布、停止播放、leave，再用新租约 join。每个异步回调携带本地 generation 标记，旧回调不能把新状态改为 connected。切换期间点击开麦不排队自动执行，到达后必须再次主动开麦。
开麦需要当前 connected、有效租约、应用前台、系统权限与明确操作。拒绝授权仍允许听音。按住说话在 pointer cancel、失焦、导航离开、后台或网络变化时立即停止；普通开关麦是等价可访问入口。只申请麦克风，不申请摄像头。
收到 WS 断开立即本机停音并 leave；服务端最迟在租约超时后回收。重连先获取最新游戏和语音投影，再申请授权，默认关麦。实时媒体与控制网络独立，RTC 仍连着不等于仍有游戏控制权。后台不启用持续录音保活，来电中断按后台同样收口；返回前台需恢复授权。
用供应商 SDK 处理音频路由、回声消除和设备切换。Flutter 播放剧情音频的插件与 RTC 共享系统音频会话，由一个 AudioSessionCoordinator 调停，不能各自反复重设路由。蓝牙掉线自动关麦并提示当前播放设备；外放与耳机分别实测回声和音量。真人发声时 BGM 在 120ms 内降低 8dB，最后发声结束 800ms 后于 280ms 恢复；旁白音量独立，用户可关闭自动压低。
## 7 故障与最小供应商边界
客户端模块提供 join、leave、setMicEnabled、setPeerMuted、setOutputVolume 和观察状态事件。服务端模块提供 issueToken、retireRoom、normalizeProviderError，不伪装成跨供应商完全通用框架；记录 provider 用于审计，未来换供应商按新房切换，活动房不热迁移。
火山 BanRoomUser 文档标明请求频率上限 40 QPS；建议以账户共享的 20 QPS 作为本功能预算，其余留给后台管理，429 指数退避加抖动。每个频道同一 retirement 合并一次调用；批量步结算先去重频道，不能按玩家重复封整房。容量以每秒频道变更数估算，不只看同时在线人数。
SDK、Token 签发、网络路由、封禁时延和后台行为需用真正 Flutter 客户端验证。本包 HTML 只验证视觉与交互，设计状态机实验不证明真实 RTC 隔离。来源与查阅日期见 sources.json。
