# 1 信息结构
工作台以项目中的一个共享世界模型为源，主画布为地点地图。左侧是地点/角色/物品/线索/事件/素材索引，中央地图容器，右侧属性与引用，底部校验或试玩记录。切换事件视图只是改变观察角度，选中ID、地点面包屑和过滤条件保持，不复制另一套角色行动图。
地点可包含对象、NPC和入口。行动附着于地点或对象；条件可引用角色能力、知识、物品和世界变量；效果链接事件或状态。作者在餐厅点餐具就能编辑“检查餐具”，查看可能获得的信息和影响的后续事件。跨地点引用显示定位按钮，不要求作者在多张无上下文flow间查找。
# 2 创作生命周期
新建项目时选择标题、固定席位数、题材及规则配置；生成可编辑空世界而非隐藏业务默认。至少创建起点和结局规则才能发布。项目可复制为新项目，全部内部ID建立映射，媒体可复用不可变资源引用但权限重新校验。
手工编辑与小说改编都产出draft。自动保存每2s静默提交变更，显式保存立即触发；断线保持本地草稿并标明未同步。撤销/重做只操作当前草稿patch，已发布版本不可撤销。多人顺序编辑用revision冲突处理，本轮不承诺多人同时在同一画布实时协作。
删除实体前列出引用位置、触发条件和受影响路径，作者选择重定向或取消；默认禁止留下悬空引用。画布折叠、缩放、排列不会修改世界可达性；通路创建必须明确方向、可见条件、通行条件与费用。
# 3 属性与操作编辑
|对象|必须配置|检验|
|地点|id、名称、起始可见性、场景素材|存在入口或明确仅叙事用途|
|角色|初始地点、个人目标、起始知识与物品|席位唯一，秘密受众一致|
|行动|label、target、cost、显示/执行条件、结果|费用非负，0费状态写有次数上限|
|通路|from、to、方向、费用、条件|引用有效；单向明确提示|
|事件|trigger、condition、priority、effects、once|循环、结局优先级与默认结束路径|
|线索|正文、来源对象、初始受众、分享策略|只读可见性预览不泄露隐藏元数据|
|媒体提示|asset_id、受众、blocking、摘要|有替代文本且受众不越权|
属性编辑器使用结构化条件构造器，支持“全部/任一/非/比较”；高级JSON编辑也必须过相同Schema。无任意JS/Python脚本字段。自然语言描述与实际效果并排显示，预览显示“文字说已打开但效果未改变门”的矛盾。
# 4 小说到可玩世界
导入支持UTF-8 TXT及正文DOCX，PDF/扫描OCR暂不承诺自动高质量解析，显示可转换格式与错误原因。先确认用户拥有处理权并记录来源说明；不自动发布导入全文。章分割预览允许作者修正后再启动任务。
任务流程：建立章与段落ID→抽取人物地点物品和事件→跨章消歧与时间线→提出可玩地点/角色/秘密分配→作者选定改编取向→生成DSL候选→校验与试玩。小说线性事件不天然有分支，AI必须把原文事实、推断和新编玩法分别标注。
作者可以接受某条分支而拒绝其他补写。改编应用生成patch，使用base_revision做三方合并；人工锁定字段优先保留，冲突进入逐项选择，禁止整份覆盖。章节内容变化按依赖图标记受影响实体与事件，重跑相关阶段，保持已有稳定ID。
# 5 预览与可玩性校验
预览启动隔离模拟房，作者可切换角色视角、注入可见状态、推进时钟、选择随机seed和AI桩。每步显示行动点前后、授权知识、事件触发原因与媒体cue；这些调试信息不进入玩家包。多人预览提供分屏，切视角不会把前一角色缓存带入下一角色。
静态校验分error/warning/info：Schema和未知引用、权限泄露、无终态、事件无界循环是error；高分支数量、某角色长期无推荐行动、素材过大是warning。图可达性只是必要条件；需用路径模拟验证状态条件下能到终局。warning可带理由豁免，error阻止发布。
校验报告包含code、entity_id、JSON Pointer、message、safe_fix和相关路径；点击定位属性，修复后可重跑单项及受影响依赖。不得因为画布看起来连通就通过。
# 6 审核 发布与运营
作者提交候选内容hash、Schema版本、素材清单和测试报告；审核人多角色试玩，批准绑定同一hash。草稿改动使审批失效。发布事务生成不可变release并更新current_release指针，失败可按幂等键查询，不重复发布。发布者必须能看见支持人数、规则版本与资产授权情况。
普通撤回只影响新房；安全blocked显示影响房间数及原因，暂停未结算房并撤销新素材访问。作者归档项目后不能新建发布，旧发布引用保留。反馈以content_hash和entity_id定位，不让玩家截图携带别人秘密。
# 7 实施与验收
React Flow只承担显示、连线、选中与拖拽；领域存储、验证器、编译器和版本服务独立于画布。先实现地点容器与对象属性的纵向编辑，再补事件叠层和小说任务，但D07全部能力仍属完整设计。
QA15验证在同一地点上下文修改线索与事件、保存恢复、撤销、删除引用和revision冲突；QA16验证非法包阻止发布及旧房保持版本；QA17—18验证来源追溯和保护人工修改。配套studio.html用于交互审查，react_flow_probe.tsx用于真实组件嵌入实验，未声称生产工作台已实现。
# 8 草稿合并与恢复细则
作者保存使用base_revision和operations。普通保存采用完整草稿PUT与If-Match；冲突后客户端取最新版本比较，再经作者确认以最新revision提交。两位作者改不同字段时，客户端展示三方合并，只建议应用各自before_hash仍匹配的字段；同一字段冲突返回412和授权差异，不自动选择最后写入。布局revision独立，画布拖拽不应导致剧情文本冲突。恢复本地草稿时展示来源版本与时间，作者可比较后应用，不静默覆盖服务器。
项目导出包含story JSON、editor_layout、资产清单、来源索引和版本说明；不得导出玩家房间数据。导入先建隔离候选并检查重复ID与路径穿越，资源上传只接受允许类型，不执行内容中附带代码。导入错误可以下载定位报告并重新提交，已完成素材不必重复上传。

草稿允许保存语法有效但业务未完整的JSON，并携带校验问题；缺地点、未设结局或未绑素材不会让作者无法保存工作。运行预览要求相关路径可执行，发布必须通过完整Schema及语义校验。字段修改和草稿读取始终校验项目权限与请求大小，不能借草稿机制执行任意代码。
