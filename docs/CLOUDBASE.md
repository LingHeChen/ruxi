## 部署前置项

`cloudbase/deployment.json` 记录目标拓扑，不是声称已部署成功的执行结果。
核心服务使用 `infra/core.production.Dockerfile` 构建 OTP release。
生产镜像不自动建库、迁移或写入种子，迁移及种子必须作为独立操作验收。
示例配置见 `cloudbase/core.env.example`，实际凭据只存忽略的 `.local` 或平台运行配置。

尚需确认 PostgreSQL 原生连接密码、Cloud Run 到数据库的受支持网络路径，以及实际 VPC/子网。
共享数据库密码不可为本项目擅自重置；网络标识不可猜测。
现有后端依赖 SQL 事务、行锁及连接会话，不能用逐次 HTTP SQL 调用替代。

注销台账必须放在独立持久存储中，具备重启恢复和备份恢复后的重放能力；
容器临时目录不能作为生产注销台账。完成挂载及写权限校验前不得宣称达到运营标准。

初期核心服务固定单实例，以匹配当前房间注册及本机 PubSub 的实现。
横向扩容须完成跨实例路由、事件分发与故障转移验收后才能开放。
前端应建立独立托管应用，避免覆盖环境已存在的共享根站点。
